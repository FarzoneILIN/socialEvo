合计 368 条模型回复。它们来自按任务整理的完整本地导出中的首个冻结场景，选取不查看实验结果；回复数不等于独立任务数。`sources.json` 记录来源文件哈希、所选场景和抽取范围。

## 原始记录

每个任务有四个 JSONL 文件，均为 UTF-8，一行一个对象：

- `cases.jsonl`：`source_run` 标记来源批次，`case` 保存原场景对象及研究者评分依据。
- `planned_slots.jsonl`：原计划请求位、条件、角色、重复编号及依赖。计划存在不表示已执行。
- `requests.jsonl`：实际提示 `input`、原始回复 `response`、原评分 `score`、状态和原 JSON 字段哈希。
- `attempts.jsonl`：逐次请求时间、失败和重试。它们不是额外实验样本。

用 `source_run + case_id` 关联场景，用 `source_run + slot_id` 关联请求。实际可见信息只以 `input` 为准；`case` 中的答案、完整库存、雷位置和求解依据属于研究者侧，不应整体作为主体输入。不同条件不能拼成连续对话，JSONL 行序也不保证并行调用的全局时间顺序。

## 实验解释

这是本地改造任务的局部消息与决策片段，不是原基准完整评测集。菜单主要检验信息补足；扫雷区分实际安全和可证明安全；谈判区分提案潜在收益和接受后兑现的收益；厨房区分局部操作和整场送餐。数独正式通信主对照仍无回复，前置能力检查不能当作通信效果结果。

[2026 年 10 月 12 日进展材料](progress_2026-10-12.md)的汇总数值来自更大的完整批次及指定配对子集，本次九个场景不能独立重算全部比例。材料原样保留，数独实际前置记录的细分状态以本说明为准。

历史回复声明包含 `gpt-5.4-2026-03-05` 与 `gpt-5.4`。补强过程中更换过服务，别名的底层日期权重未经核实；本样例用于复核过程，不用来比较不同服务的模型能力。

## 检查

在 `code/atomic_exploration/` 中执行 `python -B tools/review_data.py` 可检查数量、关联和原 JSON 哈希；加入 `--replay` 可重建补强与数独记录，厨房另按代码 README 准备固定资源。此过程不调用模型。
